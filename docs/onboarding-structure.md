# 온보딩 구조 (MVP P0)

## 목적
- 서비스 목적, 입력 방식, 결과 보는 법, 판정 분류, 예외 안내를 첫 사용/첫 분석 전에 짧게 안내
- 추후 캐릭터/친근한 안내 요소가 붙더라도 구조는 먼저 확정

## 진입 시점
- 최초 방문/첫 분석 전
- 결과 화면에서 “이 결과가 왜 이렇게 나왔는지” 도움말
- 헤더/사이드 도움말 버튼
- 스킵 가능, 다시 보기 가능

## 온보딩에서 보여줄 내용
- 서비스 목적: 전처리 코드를 넣으면 데이터 누수 의심 패턴을 줄 번호+수정 방향 위주로 짧게 보여줌
- 입력 방식: 코드 문자열 우선(파일 업로드는 추후 확장)
  - 예시: pandas, sklearn 등을 쓰는 전처리 코드 붙여넣기
- 결과 보는 법:
  - 분류(확정위반/의심/이상없음)
  - 요약(건수)
  - 각 항목: 줄 번호, 판정 유형, 수정 방향, 이유
- 판정 분류 설명:
  - 확정위반: 명확히 의심되는 패턴
  - 의심: 확인/검토가 필요한 패턴
  - 이상없음: 명확하게 의심되는 패턴이 보이지 않음
- 예외 안내:
  - 빈 입력
  - 파이썬 코드로 보기 어려운 경우
  - ML 전처리/학습 패턴이 충분하지 않은 경우
  - 분석 제한 가능성
- 가림/공개 개념(추후 확장): 기본은 민감 정보 가림, 공개 토클 시 노출 여부 결정

## UX 구성
- 단계별/짧게 안내, 스킵 가능
- 예시 코드 제공(복사해서 바로 테스트 가능)
- 결과 해석 예시(화면에 실제 결과 나올 때 참고용)
- 도움말/재확인 경로

## 참고사항
- 온보딩은 MVP P0에서 최소 안내 수준으로 시작
- 캐릭터/친근한 요소는 추후 추가(구조 먼저 확정)
